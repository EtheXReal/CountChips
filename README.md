# 筹码结算器

家里打牌用的结算小工具：拍一张全桌照片，自动按座位数筹码，核对总账，算出每人输赢和谁转给谁多少钱。数错的地方可以直接加减。

页面作为 Claude Artifact 运行（拍照识别要用到 Claude）。在线页面：https://claude.ai/artifact/LDkusipZaLBsfhZoXTkZ7f （私有，在页面的分享菜单里分享后别人才能打开）。直接用浏览器打开 `web/chip-settle.html` 也能当手动计算器用。

## 本桌规则（默认值，页面里可改）

- 黄 1000、紫 500、黑 100、蓝 10
- 红色是借款标记：每枚 = 向银行借 2000 筹码 = 20 元，结算时扣除
- 100 筹码 = 1 元
- 玩家：1 号姥姥、3 号弟弟、5 号我、6 号妈妈、10 号姥爷

## 怎么用

1. 每人把筹码按颜色摊开（见下面的拍照要领），手机举到桌子正上方拍一张，四周座位号都要入镜。
2. 在页面里点“拍全桌照片”或“从相册选”。
3. 等一两分钟：页面先让 Claude 找出每个人筹码的位置，再把每个人那一块放大单独数。
4. 看“结算”里的总账：非红筹码合计应该等于红色枚数 × 2000。不平时页面会提示最可能错在哪种颜色，并列出 Claude 没把握的那几排。用 − / + 改，或者点“近拍此人”补拍一张。
5. 账平以后页面给出最少几笔转账，“复制结算结果”可以直接发到群里。

## 为什么这样设计

- **先定位，再放大数**：发给 Claude 的图片会被压到约 120 万像素，整桌照片里一枚筹码只剩几个像素宽。所以先在整张图上找到每个座位的范围，再把每个座位裁出来放大（最多 4 倍）单独数。
- **数边，不数条纹**：摊开的一排里，每枚筹码只露出一条完整的外边；印的内圈、字和边上的花纹都不算。提示词里写明了这一点。
- **总账兜底**：桌上的筹码都是借来的，所以非红筹码合计必须正好等于红色枚数 × 2000。差额能说明错在哪种颜色，比如差 1000 多半是黄，差 30 多半是 3 枚蓝。
- **摆法比算法重要**：挤得太紧的一排，每枚只露几个像素，放大以后也分不清。照拍照要领摆，识别才靠得住。

## 拍照要领

1. 每人把筹码按颜色分开，各摊成一排，每枚至少露出约四分之一的边，不要整摞叠着。
2. 红色借款筹码单独完全摊开。
3. 同一种颜色三十枚以上，摊成两三排。
4. 从桌子正上方拍，光线均匀，不开闪光。

## 文件

- `web/chip-settle.html`：页面源码。按 Claude Artifact 的格式写，不含 `<!doctype>`、`<html>`、`<head>`、`<body>`，发布时由平台补上。
- `tests/e2e.js`：在无头 Chromium 里用一个假的 Claude 跑通整个流程（读照片、定位、裁图、解析结果、总账、转账），不消耗 Claude 用量。

## 开发

```sh
npm install
npx playwright install chromium
npm test
```

拍照识别用的是 Artifact 的 `sample` 能力，发布时要声明 `{"sample": {"images": true}}`。改完页面后，让 Claude 用 Artifact 工具把 `web/chip-settle.html` 发布到上面那个链接（带上原链接，否则会生成一个新页面）。

数量和设置只存在浏览器的 localStorage 里；拍照识别用的是打开页面那个人自己的 Claude 用量。
